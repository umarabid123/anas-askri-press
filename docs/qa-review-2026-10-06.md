# Workshop workflow review — 6 October 2026

## Purpose understood

This is an owner/staff desktop application for Arki Press & CNC Shop. Operators type custom goods/services directly into invoices, collect cash/bank payments, track customer credit, and split bill labor across workers. Customer debt and worker liability are separate ledgers. Historical invoices, offline operation, printing/PNG sharing, and recoverable backups are required.

The latest free-form billing decisions in PRD and memory take precedence over older catalog/future-cloud wording in architecture. The PRD arithmetic example has an error: 6,400 + 2,250 + 1,800 equals 10,450, not 9,450. With 5,000 labor, the undiscounted total is 15,450.

## Test isolation

This origin has separate browser storage from the user's running app on port 5173. Only fictional QA records were created. No live cloud data was written. Source files were not changed during review.

## Confirmed code defects and gaps

1. Labor UI/store writes `mazdoorName`, while browser service, Rust DTO, invoice and sync read `workerName`. Worker assignments are lost.
2. Bill validation filters blank-description items after computing totals over every row. Persisted invoice items can disagree with its header totals.
3. Payment has no total cap and remaining credit is clamped to zero, contrary to the PRD's explicit prohibition on overpayment without a dedicated workflow.
4. Reports sum payments recorded on invoices, omitting later customer receipts. Invoice history should retain original payments, but collection reporting must include receipt transactions.
5. Cloud sync only handles customer and sale entities. Unsupported payments can be marked synced; customer DELETE is treated as an upsert. Worker, payment and ledger persistence is incomplete. Empty customer UPDATE payloads from native receive_payment cannot populate the required customer fields.
6. Native get_sales returns invoice headers without item rows; historical native invoice preview therefore cannot reconstruct item details. Reports load only the latest 500 invoices.
7. Backup exports at most 1,000 sale headers on desktop, omits customer ledger/payments/item details, and uses plain JSON despite an encrypted-backup claim. Restore is absent.
8. Browser invoice numbers are random ARKI numbers, ignoring configured prefix/sequence and allowing collisions.
9. Repository Supabase policies grant anonymous full access. Exposure depends on whether these policies are deployed; live policy configuration was not inspected.

## Limits

Rust and Cargo are not available through the machine's PATH, so the native desktop build/SQLite behavior was reviewed from source, not executed. Actual printer output, WhatsApp delivery, live cloud synchronization, restore, and sustained high-volume use remain unverified. No WhatsApp message was sent. The previous .env working-tree modification was left untouched.

## Priority

Fix financial validation and worker posting first; then receipt reporting and invoice reconstruction; then reliable sync, access policies, complete backup/restore and native/printer validation. The current browser app demonstrates several successful workflows, but the full desktop/cloud product is not yet verified for shop use.

## Resolution update

The review findings above were addressed in the current working tree. Billing
now uses one shared validator; a saved invoice posts named worker labour,
receipts, customer ledger entries and correct header totals in one local
transaction. Later customer receipts feed reports. Invoice numbers use the
configured prefix/sequence, historical invoice details are reconstructed, and
financial history uses reversals instead of deletion.

Backup/restore now uses a complete versioned snapshot with relationship and
financial validation, a pre-restore recovery copy and explicit cloud-upload
pause. The cloud migration removes anonymous access, requires an approved
shop account, accepts atomic complete batches and protects historical records.

Verification after the fixes: 20 automated tests pass, the frontend production
build passes, and an isolated local PostgreSQL test verified authorization,
atomic sync, idempotency, rollback and cloud export. Browser QA verified an
invoice with Rs 50 named labour creates a worker liability and a later Rs 50
receipt appears in report collections. Native desktop compilation, physical
printing, actual PNG save dialog behavior, WhatsApp delivery and a live
Supabase deployment remain release checks because this workstation does not
have Cargo/MSVC available and no live shop account or printer was used.
